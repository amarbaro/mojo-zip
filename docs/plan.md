## Dependencies and licence
- `gzip` (raw deflate `compress(..., format="raw")` / `decompress(..., format="raw")`, `crc32`) and `mmap` (`MappedFile`): vendored under `src/gzip`, `src/mmap` for a clone build (prometheus precedent); `[tool.mojo] deps` pins `mojo-gzip >=0.1.2,<0.2`, `mojo-mmap >=0.1.0,<0.2`.
- Behaviour is ported from CPython zipfile (PSF-2.0): ship `LICENSE-PSF-2.0` with the CPython copyright line, NOTICE line, README licence line (protocol "ported code without upstream notice").
- System `libz.so.1` loaded at run time (through mojo-gzip). Stated in README.

## Error contract
Mojo `Error` text is `<PythonClass>: <str(args[0])>`; the gate compares the full line with the oracle's `type(e).__name__ + ": " + args[0]` for classes **BadZipFile, KeyError, LargeZipFile, ValueError, RuntimeError, NotImplementedError, EOFError**. `KeyError` prints the unquoted message (args[0]), not `str(e)`. Errors from the inflate backend (`zlib.error`, text differs between Python and mojo-gzip) compare as `error: zlib` only ("same behaviour, own error text"). `UnicodeDecodeError` compares as kind only.

## API (Mojo)
Constants `ZIP_STORED=0`, `ZIP_DEFLATED=8`, `ZIP64_LIMIT=(1<<31)-1`, `ZIP_FILECOUNT_LIMIT=65535`, `ZIP_MAX_COMMENT=65535`.

- `struct ZipInfo(Copyable, Movable)`: `orig_filename: String`, `filename: String` (NUL-truncated, `\` not touched on POSIX), `date_time: Array[Int, 6]`, `compress_type: Int`, `compress_level: Int` (-1 = Python `None`/default), `comment: List[UInt8]`, `extra: List[UInt8]`, `create_system, create_version, extract_version, reserved, flag_bits, volume, internal_attr, external_attr: Int`, `header_offset: Int`, `CRC: UInt32`, `compress_size: Int`, `file_size: Int`, `_end_offset: Int` (-1 = None).
  - `ZipInfo(filename="NoName", date_time=(1980,1,1,0,0,0)) raises` -> `ValueError: ZIP does not support timestamps before 1980` when `date_time[0] < 1980`. Defaults as Python (create_system 3, versions 20).
  - `is_dir() -> Bool` (`endswith("/")`; POSIX has no altsep).
  - `file_header(zip64: Bool) -> List[UInt8]` (src l.518-566, zip64 extra APPENDED to `extra`, sizes 0xffffffff, min_version 45, data-descriptor flag zeroes CRC/sizes).
- `struct ZipReader`: `ZipReader.open(path) raises` (mmap) / `ZipReader.from_bytes(var data: List[UInt8]) raises`; `namelist() -> List[String]`, `infolist() -> List[ZipInfo]` (ref), `getinfo(name) raises -> ZipInfo`, `read(name) raises -> List[UInt8]`, `read_view(name) raises -> Span[UInt8, _]` (**added**: zero copy, STORED members only, CRC checked, `NotImplementedError` otherwise; plan item), `comment: List[UInt8]`, `testzip() -> Optional[String]`, `start_dir`, `__len__`.
- `struct ZipWriter`: `ZipWriter.create(path, compression=ZIP_STORED, compresslevel=-1, allow_zip64=True) raises`; `writestr(name: String, data: Span[UInt8,_], compress_type=-1, compresslevel=-2, date_time=(1980,1,1,0,0,0))` and `writestr(var info: ZipInfo, data)`; `mkdir(name)`; `set_comment(b)`; `close()` (central directory + zip64 records). **CHANGED**: `allowZip64` is spelled `allow_zip64` (Mojo naming, same meaning); the name overload takes `date_time` with the `ZipInfo` default because Python's `now()` default is non-deterministic (SOURCE_DATE_EPOCH honoured: `date_time` argument wins when given, else env, else 1980-01-01). Rest of `_for_archive` copied: `external_attr = 0o600<<16`, dirs `0o40775<<16 | 0x10`, `compress_type`/`level` from the archive.
- Writer also has `ZipWriter.to_bytes()` (in memory) so tests need no files.

## Oracle list (confirmed against the source; each item = at least one scenario row, F = fuzz/mutation only)
End-of-central-directory (l.285-402)
1. no EOCD / empty file / file shorter than 22 bytes -> `BadZipFile: File is not a zip file`.
2. EOCD without comment (fast path, `data[-2:] == \0\0`) vs with comment (rfind in last 65557 bytes); comment 0, 1, 65535 bytes; EOCD signature inside the comment (rfind finds the LAST one); declared comment size larger than data (comment truncated, not an error).
3. truncated EOCD record in the scan window (`len(recData) != 22` -> not a zip file).
4. zip64 locator present: `disks > 1` or `diskno != 0` -> `BadZipFile: zipfiles that span multiple disks are not supported`; `reloff > offset` -> `Corrupt zip64 end of central directory locator`; record missing -> `Zip64 end of central directory record not found`; `diroffset+dirsize != reloff` or `sz+12 != 56+extrasz` -> `Corrupt zip64 end of central directory record`; zip64 EOCD "extensible data" (extrasz > 0); zip64 with prepended data (the `reloff != offset` retry); locator at offset < 0 (file too small) -> plain endrec.
5. prepended data (self-extractor): `concat = location - size_cd - offset_cd`, `header_offset + concat`; negative `start_dir` -> `BadZipFile: Bad offset for central directory`.
Central directory (l.1564-1640)
6. `Truncated central directory` (fewer than 46 bytes left), `Bad magic number for central directory`; entry count in EOCD is NOT used (loop is `total < size_cd`); trailing bytes in CD after last entry < 46 -> Truncated.
7. name decode: flag 0x800 -> UTF-8 (invalid -> UnicodeDecodeError), else cp437 (all 256 bytes map, incl. 0x80-0xFF and control bytes); NUL in name truncates `filename` but `orig_filename` keeps it; duplicate names: both in `infolist`, `NameToInfo` keeps the LAST, `getinfo` returns the last, `namelist` lists both.
8. `extract_version > 63` -> `NotImplementedError: zip file version %.1f` (e.g. `6.4`); version exactly 63 accepted.
9. date/time decode `((d>>9)+1980, (d>>5)&0xF, d&0x1F, t>>11, (t>>5)&0x3F, (t&0x1F)*2)` with invalid values (month 0 and 15, day 0, hour 31, min 63, sec 62) kept verbatim.
10. extra field loop (`_decodeExtra`): `Corrupt extra field %04x (size=%d)` when `ln+4 > len(extra)`; trailing < 4 bytes ignored; zip64 field fills file_size (when 0xFFFFFFFF or 0xFFFFFFFFFFFFFFFF), then compress_size (when 0xFFFFFFFF), then header_offset (when 0xFFFFFFFF), in that order, field-by-field consumption; short data -> `Corrupt zip64 extra field. File size not found.` / `Compress size not found.` / `Header offset not found.`; zip64 field with MORE data than needed (ignored); two zip64 fields; unicode path field 0x7075: version 1 + matching name CRC replaces filename (sanitized), version != 1 or CRC mismatch ignored, empty name -> warning only, short data (`< 5` bytes) -> `Corrupt unicode path extra field (0x7075)`, bad utf-8 -> `Corrupt unicode path extra field (0x7075): invalid utf-8 bytes`.
11. `_end_offset` computation (sorted by header_offset, ties: stable sort, reversed).
Open / read (l.1730-1830, 1124-1232)
12. `Truncated file header` (local header cut), `Bad magic number for file header`; local name vs central name: `File name in directory %r and header %r differ.` (the first %r is `orig_filename` str repr, the second is the raw BYTES repr `b'...'`); local extra length skipped; local flag 0x800 decides local name decoding.
13. flag bit 5 -> `NotImplementedError: compressed patched data (flag bit 5)`; bit 6 -> `strong encryption (flag bit 6)`; bit 0 -> `RuntimeError: File %r is encrypted, password required for extraction` (name as given to `read`, no decryption: Known limit); order of these checks (patch, strong, name, overlap, encrypt).
14. overlap detection: `data_start + compress_size > _end_offset` -> `BadZipFile: Overlapped entries: %r (possible zip bomb)`; when `_end_offset == header_offset` (same offset twice) only a warning, read continues.
15. compress types: 0, 8; 12/14/93 are SUPPORTED by CPython but NOT by us (Known limit: `NotImplementedError: compression type 12 (bzip2)` own text, tested outside the oracle diff); other known names from `compressor_names` (1..10, 18, 19, 97, 98) -> `compression type %d (%s)`; unknown (e.g. 77) -> `compression type 77`. Check order: compress type error happens in `ZipExtFile.__init__` AFTER flags/name/overlap/encrypt checks.
16. read semantics: output truncated to `file_size`; `file_size == 0` returns b"" but CRC still checked at eof? (verify: `_left <= 0` sets eof and `_update_crc(b'')` raises on CRC mismatch) -> scenario; `file_size > actual` for stored -> CRC error not size error; deflate stream shorter -> `EOFError`; corrupt deflate -> zlib.error (kind only); truncated archive file with intact CD -> EOFError; data descriptor (flag 3) archives read with CD sizes; CRC mismatch -> `Bad CRC-32 for file %r` (uses `ZipExtFile.name` = `zinfo.filename`, i.e. the sanitized/unicode-path name).
17. `getinfo` missing -> `KeyError: There is no item named %r in the archive` (repr with quotes and escapes of non-ASCII, `\n`, quotes: needs a `repr` helper, oracle rows with `'`, `"`, newline, non-ASCII).
18. `testzip()` returns first bad name (filelist order) or None; swallows only BadZipFile (EOFError/zlib propagate).
Writer (l.1829-1870, 1977-2225, 1370-1410)
19. byte-identical archive for fixed `date_time`/level: STORED and DEFLATED at levels -1, 0, 1, 6, 9 (levels outside -1..9: zlib error -> `error: zlib`), non-ASCII names (cp437 encodable -> flag 0x800 cleared; else UTF-8 + flag set; ASCII), empty data (deflate of b"" is 2 bytes `\x03\x00`), data 1 byte, 65536/65537 bytes, incompressible random data (deflate larger than stored), dir entry `a/` (`mkdir`), explicit ZipInfo fields (extra, comment, external_attr, create_system, internal_attr, flag_bits 0x08 is OVERWRITTEN to `0x800` on write: `flag_bits = _MASK_UTF_FILENAME`), archive comment, comment > 65535 -> truncated + warning, empty archive (22-byte EOCD).
20. zip64 write paths (need big sizes without big data: `ZipInfo.file_size` sets are overwritten by writestr, so zip64 scenarios use `force`-like small cases via the module constants): the Python oracle monkeypatches `zipfile.ZIP64_LIMIT` and `ZIP_FILECOUNT_LIMIT` (reading them at call time) and the Mojo side exposes the same two values as runtime settings `ZipWriter.zip64_limit`, `.filecount_limit` (default the real constants). Covers: file header zip64 extra appended + 0xffffffff + version 45; central directory zip64 extra PREPENDED after `_Extra.strip(extra, (1,))` (any user zip64 field removed, user fields keep order), with `[file_size, compress_size]` when either exceeds, `[header_offset]` when offset exceeds, all three; zip64 EOCD + locator when count/offset/size exceed; `allow_zip64=False`: `LargeZipFile: Filesize would require ZIP64 extensions`, `Zipfile size would require ZIP64 extensions`, `Files count would require ZIP64 extensions`, and at close `Central directory offset|size / Files count would require ZIP64 extensions`; `zip64 = file_size*1.05 > ZIP64_LIMIT` float test on the way in; compressed size over the limit while uncompressed is below -> `RuntimeError: Compressed size too large, try using force_zip64` (and `File size too large`).
21. `_writecheck`: `Duplicate name: %r` is a warning (both entries kept); unsupported compress type on write -> `NotImplementedError: That compression method is not supported` for ids outside {0,8,12,14,93}; 12/14/93 own limit text.
22. `writestr(ZipInfo)` mutates the passed info (`header_offset`, `CRC`, sizes, `flag_bits`, `external_attr` default `0o600<<16` only when 0) - check via reading back the archive.
23. Python reads every Mojo archive (`testzip() is None`, all bytes equal) and Mojo reads every Python archive (property rows).
24. `is_dir`, `ZipInfo` date before 1980 -> `ValueError`; `date_time` at upper edge (2107, 12, 31, 23, 59, 58) and odd seconds (rounded down by `//2`).
Not covered, listed as Known limits: encryption (flag 0 data decrypt), bzip2/lzma/zstd, append mode `a`, in-place `remove`, streaming `open(..., 'w')`/non-seekable data-descriptor writes, `ZipFile.extract*`, `Path`, `metadata_encoding`, `printdir`, `is_zipfile`.

## Bytes equality rule
Writer output byte-identical to CPython `ZipFile.writestr(ZipInfo)` for the same ZipInfo (fixed date_time) EXCEPT where zlib builds differ: both sides use system libz (Python 3.14.9 from `/usr/bin/python3` links the system zlib; the oracle records `zlib.ZLIB_RUNTIME_VERSION` and `ZLIB_VERSION` in its first line and the gate compares only after checking they equal `libz.so.1`'s version; if they differ, deflate rows compare after inflate, and say so). Reader: every field of every ZipInfo + read() bytes equal to Python.

## Hot path + memory budget (measured baselines go to `.work/baseline.md` before src)
Hot paths: (a) `ZipReader` open + `infolist` over a 100,000-entry archive; (b) `read_view` of a 1 GB STORED member (zero copy: peak RSS stays ~ file size mapped, resident only touched pages for CRC) and `read` of a 64 MB DEFLATED member.
- Budget: central directory parsed in one pass into a flat `List[ZipInfo]`; per-entry heap = name String + extra + comment only when non-empty (empty `List` allocates nothing); target <= 200 B/entry beyond the name; `size_of[ZipInfo]()` recorded. Names in an arena only if it measures >= 5% better.
- STORED read = `Span` view, no copy; `read` copies once. DEFLATED = one `decompress` call sized by `file_size` (known up front: inflate straight into an output of `file_size` bytes, no `*4` growth loop; mojo-gzip's `decompress` grows by doubling, request a `decompress_into` variant from the builder only if the doubling costs > 5%).
- Writer streams: holds at most the one member being compressed plus the central-directory list; output buffered through one `List[UInt8]` flushed per member (never the whole archive) unless `to_bytes`.
- CRC via zlib `crc32` over the whole span (zero copy).
- Bench program written FIRST: `bench/zipbench.mojo` + `tools/bench_ref.py`; baseline commands: `/usr/bin/time -f '%e s %M KB' python3 -I tools/bench_ref.py`; `heaptide run` for leaks.

## Gates
Golden rows (`tools/gen_vectors.py`, deterministic, seed fixed): generated archives are stored as hex in `tests/golden/vectors.txt` (small) and big ones (zip64, 100k entries) are generated at test time by the runner from a recipe row (no big fixtures committed). Row: `index op arg... -> status result`. Ops: `read` (ZipInfo dump of every entry + sha256 of every member or the error line), `write` (recipe -> hex of archive bytes or error), `roundtrip`. `tools/oracle.py` replays the same rows LIVE through CPython (scenario `golden`), `tests/cases.mojo` replays them through Mojo; `scripts/check.sh` diffs, twice each.
Property test (`tests/test_roundtrip.mojo`): random members written then read back equal; Python reads every Mojo archive (in the oracle, `testzip() is None`). Mutants >= 15 (`tests/mutants.txt`). Time-boxed random differential run against CPython over mutated archives (flip bytes in EOCD/CD/local header) in `tools/fuzz.py`, counts in the report.
LOC estimate ~700 (imports: gzip raw deflate + crc32, mmap; struct not needed).
