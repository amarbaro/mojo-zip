# mojo-zip v0.1.0

**Released:** 2026-11-10 · **Commit:** the one tagged `v0.1.0` · **Previous:** first release

## What it does

`zipfile` for Mojo, in pure Mojo: read and write ZIP archives (stored and deflated members, zip64, CRC-32, archive and member comments) with CPython's `zipfile` behaviour and error texts. No C library and no FFI: the DEFLATE codec is a port of zlib 1.3.2, so the bytes it writes are the bytes `zlib` writes at every level.

## Highlights

- Deflate output is byte-identical with `zlib` at levels 0 to 9, one-shot and streaming, on 2610 generated and mutated inputs.
- Archives it writes are read by CPython's `zipfile`, and archives CPython writes are read the same by both, across 11 oracle scenarios.
- Opening and reading 100,000 entries takes 0.06 s and 54 MB, against 0.27 s and 76 MB in CPython (`docs/perf.md`).
- Inflate runs at the speed of C zlib or slightly faster, deflate is 7% slower at level 6 with the same output bytes (`docs/perf.md`).

## Changes

## Known limits

- Not covered: encryption, bzip2, lzma and zstd members (they raise `NotImplementedError`), append mode, in-place `remove`, streaming `open(..., 'w')`, `extract*`, `Path`, `metadata_encoding`, `printdir`, `is_zipfile`.
- The reader holds the whole archive in memory (no mmap without FFI). 64-bit sizes and offsets saturate at 2^61.
- `ZipInfo` is 264 bytes, about 340 bytes per entry at 100,000 entries, above the 200 byte target in `docs/plan.md`.
- Compressing 16 MB at level 6 takes 498 ms against 465 ms for zlib, 7% slower.

## Upgrade / run

```
git clone https://github.com/amarbaro/mojo-zip && cd mojo-zip && uv sync

```
